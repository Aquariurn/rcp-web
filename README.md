# 손끝 승부 — rcp-web

카메라에 보여준 손 모양을 AI가 인식해 컴퓨터와 대결하는 **가위바위보 웹 게임**입니다. 기본 모델이 포함되어 있어 직접 AI를 학습시키지 않아도 바로 플레이할 수 있습니다. Teachable Machine에서 학습한 자신의 가위바위보 모델로 바꿔 사용할 수도 있습니다.

**[게임 바로 시작하기](https://aquariurn.github.io/rcp-web/)**

카메라가 있는 기기와 브라우저만 준비하세요. 배포된 사이트는 별도 설치 없이 사용할 수 있으며, 페이지·라이브러리·모델을 내려받을 인터넷 연결이 필요합니다. 인터넷 없이 사용하려면 아래의 [로컬 실행 방법](#로컬에서-실행하기)을 이용하세요.

## 처음 게임을 시작한다면

1. 위의 **게임 바로 시작하기** 링크를 엽니다.
2. 기본 모델 로딩이 끝나면 **카메라 켜기**를 누르고 카메라 권한을 허용합니다.
3. 카메라에 손을 보여주고 **AI의 예측**이 원하는 가위·바위·보로 표시되는지 확인합니다.
4. **승부하기**를 누른 뒤 `3 → 2 → 1` 카운트다운이 끝날 때까지 손 모양을 유지합니다.
5. 컴퓨터의 선택과 승부 결과를 확인합니다. **한 판 더**를 누르면 다음 라운드를 시작합니다.

컴퓨터는 가위·바위·보 중 하나를 무작위로 선택합니다. 플레이어의 선택은 카운트다운이 끝난 시점의 AI 예측으로 결정됩니다.

| 화면 표시·버튼 | 의미 |
| --- | --- |
| AI의 예측 / 백분율 | 현재 인식한 손 모양과 모델의 확신 정도입니다. 백분율은 실제 정답률을 뜻하지 않습니다. |
| 나 / 컴퓨터 | 각자 이긴 횟수입니다. 무승부일 때는 점수가 오르지 않습니다. |
| ROUND | 판정이 완료된 라운드 수입니다. 무승부도 포함합니다. |
| 점수 초기화 | 양쪽 점수와 라운드 수를 초기화합니다. 카운트다운 중에는 사용할 수 없습니다. |
| 오른쪽 위 ⚙ | 자신의 모델을 적용하거나 기본 모델로 돌아가는 설정 창을 엽니다. |

판정 시 예측 확신도가 **55% 미만**이거나 인식에 실패하면 해당 라운드는 집계하지 않습니다. 손을 화면 중앙에 충분히 보이게 하고 밝은 곳에서 다시 시도하세요.

## 내가 학습한 모델로 플레이하기

### 1. 모델 준비하기

Teachable Machine의 **이미지 모델**을 사용합니다. 클래스는 가위·바위·보를 각각 하나씩, **총 3개**로 구성하세요.

| 손 모양 | 권장 클래스 이름 | 영문 이름 |
| --- | --- | --- |
| 가위 | `가위` | `scissors` |
| 바위 | `바위` | `rock` |
| 보 | `보` | `paper` |

`Class 1` 같은 기본 이름이나 별도의 `배경` 클래스를 추가한 모델은 사용할 수 없습니다. 음성·포즈 모델이나 가위바위보 이외의 분류 모델도 이 게임의 대상이 아닙니다.

학습을 마쳤다면 **Export Model → TensorFlow.js → Download my model**에서 파일을 내려받고 압축을 풉니다. 게임에서는 모델 공유 URL이나 ZIP 파일 대신 압축을 푼 파일을 선택합니다.

```text
내려받은 모델/
├── model.json       # 모델 구조
├── metadata.json    # 클래스 이름 등 모델 정보
└── weights.bin      # 학습된 가중치 — 여러 .bin 파일일 수도 있습니다
```

### 2. 게임에 적용하기

1. 게임 화면 오른쪽 위의 **⚙ 설정**을 엽니다.
2. **AI 모델 연결** 창에서 아래 표에 맞춰 파일을 선택합니다.
3. **선택한 모델 적용**을 누르고 검증과 로딩이 끝날 때까지 기다립니다.
4. **현재 모델**과 그 아래의 상태 메시지에서 적용 결과를 확인합니다.
5. 설정 창을 닫고 카메라를 켜서 플레이합니다. 이미 카메라가 켜져 있다면 새 모델로 인식을 이어갑니다.

| 파일 선택 칸 | 선택할 파일 |
| --- | --- |
| 모델 구조 | `model.json` |
| 모델 가중치 | 함께 내려받은 모든 `.bin` 파일 |
| 모델 정보 | `metadata.json` |

세 종류의 파일은 **같은 모델을 한 번에 내보낸 결과물**이어야 합니다. 파일 이름을 바꾸지 말고, 가중치가 여러 파일로 나뉘어 있다면 모두 선택하세요. 파일 선택 순서는 상관없습니다.

적용에 실패하면 설정 창에 이유가 표시되며, 사용 중이던 정상 모델은 유지됩니다. 다시 기본 모델을 쓰려면 **기본 모델 사용**을 누르세요.

### 파일과 카메라 영상은 어떻게 처리하나요?

- 선택한 모델 파일과 카메라 영상은 게임 서버로 전송하지 않으며, AI 인식은 브라우저에서 처리합니다.
- 직접 선택한 모델은 현재 탭에서만 사용합니다. 페이지를 완전히 새로고침하거나 새 탭에서 열면 기본 모델로 시작하므로 다시 선택해야 합니다.
- 다른 사람에게 게임 주소를 공유해도 내가 선택한 모델이 함께 전달되지는 않습니다. 같은 모델을 쓰려면 모델 파일도 별도로 전달해야 합니다.

## 잘 안 될 때 확인하기

| 증상 | 확인할 내용 |
| --- | --- |
| 카메라를 열 수 없다고 나와요 | 브라우저의 사이트 권한과 운영체제 설정에서 카메라 사용을 허용했는지 확인하세요. 다른 앱이 카메라를 사용 중이라면 종료한 뒤 다시 시도하세요. |
| 카메라 켜기 버튼이 비활성화돼요 | 모델 로딩이 끝날 때까지 기다리세요. 로딩 실패 안내가 나오면 ⚙ 설정에서 **기본 모델 사용**을 누르거나 모델 파일을 다시 선택하세요. |
| 손 모양이 다르게 인식돼요 | **AI의 예측**을 보면서 손의 위치·거리·조명을 조정하세요. 직접 학습한 모델이라면 학습할 때의 촬영 조건과 비슷하게 맞춰 보세요. |
| 카운트다운 후 점수가 바뀌지 않아요 | 무승부이거나 인식 확신도가 부족할 수 있습니다. 결과 메시지를 확인하세요. 인식 실패 시 ROUND도 증가하지 않습니다. |
| 인식 오류가 표시돼요 | 게임이 자동으로 인식을 재시도합니다. 정상화될 때까지 승부 버튼이 비활성화됩니다. 계속되면 기본 모델로 전환하거나 페이지를 새로고침하세요. |
| 선택한 모델 적용 버튼을 누를 수 없어요 | 모델 구조·가중치·정보 파일을 모두 선택했는지 확인하세요. 모델 로딩이나 카운트다운 중에도 일시적으로 비활성화됩니다. |
| 모델 클래스 또는 규격 오류가 나와요 | 클래스가 가위·바위·보 각각 하나인지, 파일들이 같은 이미지 모델에서 나온 것인지 확인하고 TensorFlow.js 형식으로 다시 내보내세요. |
| 가중치 파일이 없거나 파일이 너무 크다고 나와요 | 압축을 완전히 풀고 모든 `.bin` 파일을 선택하세요. 모델 JSON은 5 MiB, 정보 JSON은 256 KiB, 가중치는 합계 64 MiB·최대 32개까지 지원합니다. |
| 새로고침하니 내 모델이 사라졌어요 | 정상 동작입니다. 사용자 모델은 저장되지 않으므로 설정에서 다시 선택하세요. |

## 로컬에서 실행하기

프로젝트를 수정하거나 인터넷 연결 없이 사용하려는 경우의 실행 방법입니다. **Python 3**와 `vendor/`, `model/`을 포함한 프로젝트 전체 파일이 필요합니다.

1. 이 저장소를 내려받아 압축을 풀거나 Git으로 복제합니다.
2. 터미널에서 `index.html`이 있는 프로젝트 폴더로 이동합니다.
3. 다음 명령으로 로컬 서버를 실행합니다.

   ```bash
   python3 -m http.server 8000 --bind 127.0.0.1
   ```

4. 같은 기기의 브라우저에서 [http://localhost:8000](http://localhost:8000)을 엽니다.
5. 종료하려면 서버를 실행한 터미널에서 `Ctrl+C`를 누릅니다.

`index.html`을 더블클릭하는 `file://` 방식은 모델 로딩과 카메라 사용이 제한될 수 있으므로 로컬 서버를 이용하세요. 위 명령은 같은 기기에서만 접속하도록 서버를 엽니다.

라이브러리와 기본 모델을 프로젝트 내부에서 읽으므로, 프로젝트와 Python을 준비한 뒤에는 인터넷 없이 로컬 실행할 수 있습니다. 다른 기기로 옮길 때도 **`vendor/`와 `model/`을 포함한 전체 폴더**를 복사하세요.

## 개발 및 유지보수

### 주요 파일

| 경로 | 역할 |
| --- | --- |
| `index.html` | 게임 화면과 모델 설정 창 |
| `styles.css` | 화면 스타일과 반응형 레이아웃 |
| `app.js` | 카메라, AI 인식, 모델 교체, 승부·점수 처리 |
| `model/` | 처음 실행할 때 사용하는 기본 모델 |
| `vendor/` | 브라우저에서 사용하는 AI 라이브러리 |
| `tests/app.test.cjs` | 게임 동작과 모델 처리 자동 테스트 |
| `.github/workflows/deploy-pages.yml` | 테스트 및 GitHub Pages 배포 |

### 사이트의 기본 모델 교체하기

모든 방문자에게 제공할 기본 모델을 바꾸려면, Teachable Machine에서 내보낸 `model.json`, `metadata.json`, 모든 가중치 파일을 프로젝트의 **`model/` 폴더에서 함께 교체**하세요. 사용자 모델과 동일하게 가위·바위·보 3개 클래스를 지원해야 합니다.

가중치 파일 이름과 `model.json`의 참조가 일치해야 하므로 내보낸 파일 이름을 유지하세요. 로컬에서 모델 로딩과 실제 카메라 인식을 확인한 뒤 배포합니다. 브라우저 설정 창에서 파일을 선택하는 것만으로는 저장소의 기본 모델이 바뀌지 않습니다.

### 테스트 실행하기

Node.js 18 이상이 설치된 환경에서 프로젝트 폴더의 터미널로 실행합니다. 별도 패키지 설치는 필요 없습니다.

```bash
node --test tests/app.test.cjs
```

모델 로딩·검증·해제, 카메라 실패·페이지 이탈, 추론 오류 복구, 승패·점수 초기화를 검증합니다. 실제 모델의 CPU 추론과 가중치 해제도 확인합니다. 카메라 권한과 화면 표시는 브라우저에서 별도로 확인하세요.

### GitHub Pages 배포

현재 워크플로는 `main`에 변경사항이 반영되면 **테스트 → 사이트 업로드 → Pages 배포** 순서로 실행됩니다.

- PR을 `main`에 병합하거나 `main`에 직접 push하면 배포가 실행됩니다.
- 기능 브랜치에 push하거나 PR을 생성하는 것만으로는 이 워크플로가 실행되지 않습니다.
- 테스트에 실패하면 해당 실행에서는 배포하지 않습니다.

저장소의 **Settings → Pages → Build and deployment → Source**는 **GitHub Actions**로 설정합니다. 배포 진행 상황은 **Actions → Deploy GitHub Pages**에서 확인하고, 성공 후 실제 게임 주소에서도 동작을 확인하세요.
